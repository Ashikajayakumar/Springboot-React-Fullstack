

# 📦 1. JAR → WAR

## 📦 1. What is JAR? 
  
**JAR = Java ARchive**  
      
A JAR file is a package that contains Java application files together in a single file.  
 
💡 Think of it like a **ZIP file for a Java application**. 
 
For example:

```text
MyApplication
    ├── ☕ Java classes
    ├── ⚙️ configuration files
    ├── 📁 resources
    └── 📚 dependencies
           ↓
        📦 MyApp.jar
```

Instead of giving someone hundreds of files, we can package them into:

```text
MyApp.jar
```

---

## 📦 2. Why do we need JAR?

Suppose your Spring Boot project contains:

```text
src
 ├── main
 │    ├── java
 │    └── resources
 └── test

pom.xml
```

After building the project, Maven can package the application:

```text
🌱 Spring Boot Project
       ↓
     📦 Maven
       ↓
    🔨 package
       ↓
   📦 application.jar
```

Then you can run the application using:

```bash
java -jar application.jar
```

So:

> 💡 **JAR packages your Java/Spring Boot application into a single executable file.**

---

# 🌐 3. What is WAR?

**WAR = Web Application ARchive**

A WAR file is specifically designed for **web applications**.

Example:

```text
MyApplication.war
```

It contains things needed to deploy a web application to a **web/application server** such as Tomcat.

Think:

```text
🌐 WAR
 ↓
💻 Web Application
 ↓
🖥️ Application Server
 ↓
🐱 Tomcat
```

---

# ⚖️ 4. JAR vs WAR

The easiest way to understand the difference:

| 📦 JAR                                        | 🌐 WAR                                           |
| --------------------------------------------- | ------------------------------------------------ |
| Java ARchive                                  | Web Application ARchive                          |
| General Java application package              | Web application package                          |
| Can be executable                             | Usually deployed to a server                     |
| Spring Boot commonly uses JAR                 | Traditional Spring applications commonly use WAR |
| Can contain an embedded server in Spring Boot | Usually uses an external application server      |

---

# 🏢 5. Traditional Spring application

Earlier, a web application could be packaged as:

```text
MyApplication.war
```

Then you would deploy it to Tomcat:

```text
                🐱 Tomcat Server
                     ↑
                     │
                📦 MyApp.war
```

Tomcat runs the application.

---

# 🚀 6. Spring Boot changed this

Spring Boot makes it much easier.

A Spring Boot application can be packaged as:

```text
MyApplication.jar
```

The JAR can contain an **embedded Tomcat server**.

So:

```text
📦 MyApplication.jar
       │
       ├── 💻 Your application
       │
       ├── 📚 Dependencies
       │
       └── 🐱 Embedded Tomcat
```

Then you simply run:

```bash
java -jar MyApplication.jar
```

And the application starts.

Usually:

```text
🌐 Browser
   ↓
localhost:8080
   ↓
🐱 Embedded Tomcat
   ↓
🌱 Spring Boot Application
```

This is one of the major reasons Spring Boot is beginner-friendly.

---

# 🐱 7. What does "Embedded Tomcat" mean?

This is very important.

### 🏢 Traditional approach

You have to install/run Tomcat separately:

```text
🐱 Tomcat
   ↑
📦 WAR
```

### 🚀 Spring Boot JAR approach

Tomcat is included as part of the application:

```text
📦 MyApplication.jar
   │
   ├── 🌱 Spring Boot
   ├── 💻 Your code
   ├── 📚 Dependencies
   └── 🐱 Tomcat
```

So you don't normally need to separately deploy the WAR to Tomcat.

---

# 🏗️ 8. How does this look in a Spring Boot project?

In `pom.xml`, you will commonly see:

```xml
<packaging>jar</packaging>
```

For Spring Boot, `jar` is commonly the default packaging, so you may not even need to write it explicitly.

When you run:

```bash
mvn clean package
```

Maven creates something like:

```text
target/
    ├── 📦 crud-0.0.1-SNAPSHOT.jar
    └── ...
```

Then:

```bash
java -jar target/crud-0.0.1-SNAPSHOT.jar
```

Your Spring Boot application starts.

---

# 🌐 9. Can Spring Boot use WAR?

**Yes.** ✅

Spring Boot supports both:

```text
📦 JAR
 ↓
🐱 Embedded server
```

and

```text
🌐 WAR
 ↓
🖥️ Deploy to external server
```

But for a **new Spring Boot project**, JAR is generally the simpler choice.

---

# 🔄 10. JAR → WAR: What does that mean?

When someone tells you to study:

> **JAR → WAR**

They usually want you to understand the **different ways Java web applications are packaged and deployed**.

Think of the evolution:

### 🏢 Traditional Java Web Application

```text
Java Application
       ↓
      📦 WAR
       ↓
External Tomcat
       ↓
     ▶️ Run
```

### 🚀 Spring Boot

```text
Spring Boot Application
       ↓
      📦 JAR
       ↓
Embedded Tomcat
       ↓
     ▶️ Run
```
