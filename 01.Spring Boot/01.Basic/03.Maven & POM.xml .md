# 📦 2. Maven & `pom.xml`

Since you now understand **JAR → WAR**, the next thing is **Maven**.

The easiest way to understand it is:

> 💡 **Maven is a tool that manages your Java/Spring Boot project, especially dependencies and building the application.**

And:

> 📄 **`pom.xml` is Maven's configuration file.**

---

# 🔨 1. What is Maven?

**Maven is a build and dependency management tool for Java projects.**

It helps you with things like:

* 📥 Downloading required libraries
* 📦 Managing dependencies
* ☕ Compiling Java code
* 🧪 Running tests
* 📦 Creating JAR/WAR files
* 🏗️ Managing the project build

💡 Think of Maven as your **project manager**.

```text id="4qj6i9"
Your Spring Boot Project
          ↓
        📦 Maven
     ┌────┼────┐
     ↓    ↓    ↓
Dependencies
Compile
Build JAR/WAR
```

---

# 🤔 2. Why do we need Maven?

Imagine you create a Spring Boot application that needs:

```text id="9j2y3k"
🌐 Spring Web
🐬 MySQL
🗄️ Spring Data JPA
🌱 Spring Boot
```

### ❌ Without Maven

You would have to:

```text id="4x5h3k"
Download each JAR manually
        ↓
Put them in your project
        ↓
Check versions
        ↓
Manage dependencies
        ↓
Update them manually
```

This becomes difficult.

### ✅ With Maven

```text id="w2r8y1"
pom.xml
   ↓
Tell Maven what you need
   ↓
Maven downloads it
   ↓
Adds it to your project
```

That's the main purpose.

---

# 📚 3. What is a dependency?

A **dependency** is a library that your application needs.

For example, suppose you want to create REST APIs.

You need **Spring Web**.

Instead of writing everything required for HTTP handling yourself, you add the Spring Web dependency.

For MySQL:

```text id="v0e8cl"
Your Application
      ↓
needs MySQL connection
      ↓
MySQL JDBC Driver
      ↓
📦 Dependency
```

So:

> 💡 **Dependency = external library required by your application.**

---

# 📄 4. What is `pom.xml`?

`pom.xml` means:

**POM = Project Object Model**

It is the main configuration file used by Maven.

Your Spring Boot project usually contains:

```text id="tx9n4p"
MyProject
│
├── 📁 src
│
├── 📁 target
│
├── 📄 pom.xml       ← Maven configuration
│
├── 📄 mvnw
└── 📄 mvnw.cmd
```

The important file here is:

```text id="e3qj7m"
pom.xml
```

---

# 📝 5. What does `pom.xml` contain?

It can contain information such as:

```text id="y3x6u2"
Project information
       ↓
Spring Boot version
       ↓
Java version
       ↓
📦 Dependencies
       ↓
🔌 Plugins
       ↓
🏗️ Build configuration
```

For example:

```xml id="m7s0cz"
<project>

    <groupId>com.example</groupId>

    <artifactId>demo</artifactId>

    <version>0.0.1-SNAPSHOT</version>

    <dependencies>
        ...
    </dependencies>

</project>
```

# 🔑 6. Important parts of `pom.xml`

Let's understand them one by one.

## `groupId`

Example:

```xml id="qj2p5b"
<groupId>com.example</groupId>
```

It identifies the organization or group that owns the project.

For your own project, you might have:

```xml id="6n9f4u"
<groupId>com.ashika</groupId>
```

Think:

```text id="r2t5km"
groupId = Who/which organization created this project?
```

---

# 🏷️ 7. `artifactId`

Example:

```xml id="x3z8pq"
<artifactId>crud</artifactId>
```

This is basically the **name of your project/application**.

For example:

```xml id="v9h2ka"
<artifactId>student-management</artifactId>
```

Your generated JAR may look something like:

```text id="n8c4yz"
student-management-0.0.1-SNAPSHOT.jar
```

So:

```text id="1w6jsk"
artifactId
    ↓
Project name
```

---

# 🔢 8. `version`

Example:

```xml id="7c4q2m"
<version>0.0.1-SNAPSHOT</version>
```

This tells Maven which version of your project you're working on.

For example:

```text id="6r2x9a"
1.0.0
1.1.0
2.0.0
```

`SNAPSHOT` generally means the project is a development version.

---

# 📦 9. Dependencies

This is one of the **most important parts** of `pom.xml`.

Example:

```xml id="z8r4wp"
<dependencies>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

</dependencies>
```

This tells Maven:

> 💬 "I need Spring Boot Web."

Maven then downloads the required libraries.

---

# 🐬 10. Example: MySQL dependency

Suppose you're creating the CRUD application you've been working on.

You want to connect Spring Boot to MySQL.

You can have a dependency such as:

```xml id="2y8f1m"
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
</dependency>
```

Maven sees it and downloads the MySQL JDBC driver.

So:

```text id="4m7z9x"
pom.xml
   ↓
mysql-connector-j
   ↓
📥 Maven downloads it
   ↓
🌱 Spring Boot can communicate with MySQL
```

---

# 🌐 11. What is a Maven repository?

Where does Maven get these dependencies from?

Usually from a **Maven repository**.

Think of it like an online library.

```text id="2a7k9c"
             Maven Central
                  ↓
       ┌──────────┼──────────┐
       ↓          ↓          ↓
   Spring Web   MySQL      JPA
       ↓          ↓          ↓
              📦 Maven
                ↓
        Your local computer
                ↓
          Your project
```

Maven downloads dependencies and stores them locally, commonly in your user's `.m2` directory.

---

# 🌍 12. What is Maven Central?

**Maven Central** is a major public repository containing Java libraries and dependencies.

For example, Maven can find:

```text
🌱 Spring Boot
🐬 MySQL Connector
🧪 JUnit
🔄 Jackson
🗄️ Hibernate
etc.
```

You don't normally download each library manually.

You specify it in:

```text
pom.xml
```

and Maven handles the download.

# ⚙️ 13. What does Maven do when you run the project?

Suppose you run:

```bash id="3d9q8v"

```

Maven performs build-related tasks.

Conceptually:

```text id="8x2v5c"
pom.xml
   ↓
Read project configuration
   ↓
Find dependencies
   ↓
Download dependencies if needed
   ↓
☕ Compile Java code
   ↓
🧪 Run tests
   ↓
📦 Package application
   ↓
📦 Create JAR/WAR
```

For a Spring Boot JAR project:

```text id="7m4n2b"
target/
    └── crud-0.0.1-SNAPSHOT.jar
```

# 🧩 17. What is Maven Wrapper?

In your Spring Boot project, you may see:

```text
mvnw
mvnw.cmd
```

These are **Maven Wrapper** files.

You might see:

```text id="6c1v9x"
pom.xml
mvnw
mvnw.cmd
```

The wrapper allows the project to use a specified Maven version without requiring you to manually install/configure Maven in the usual way.

On Windows, you may commonly see:

```bash id="0j4r7m"
mvnw.cmd clean package
```

or:

```bash id="2p8s6k"
.\mvnw.cmd clean package
```

# 🎯 20. Interview questions

### ❓ What is Maven?

> **Maven is a build and dependency management tool used for Java projects. It manages dependencies, compiles code, runs tests, and packages applications into JAR or WAR files.**

### ❓ What is `pom.xml`?

> **`pom.xml` is Maven's configuration file. POM stands for Project Object Model. It contains project information, dependencies, plugins, and build configuration.**

### ❓ What is a dependency?

> **A dependency is an external library required by the application to provide specific functionality.**

### ❓ What does `mvn package` do?

> **It builds the project and packages the application, commonly into a JAR or WAR file.**
