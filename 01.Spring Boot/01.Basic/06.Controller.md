# 1. What is a Controller?              
             
A **Controller** is a Java class that handles requests coming from a client, such as:               
                
* 🌐 Browser             
* 🧪 Postman             
* 💻 Frontend application     
* 📱 Mobile application    
* 🔗 Another application

Simple definition:

> **Controller receives the HTTP request and sends the response.**

For example, a client sends:

```text
GET http://localhost:8080/students
```

The request reaches:

```text
👤 Client
   ↓
🎮 Controller
```

The Controller decides what should happen next.

---

# 2. Real-world example 🍽️

Think about a restaurant.

```text
👤 Customer
   ↓
🧑‍🍳 Waiter
   ↓
🍳 Kitchen
   ↓
🍲 Food
```

The **waiter** receives the customer's request and passes it to the kitchen.

In Spring Boot:

```text
👤 Client
   ↓
🎮 Controller
   ↓
⚙️ Service
   ↓
🗄️ Repository
   ↓
🐬 Database
```

So you can think of:

```text
🎮 Controller = 🧑‍🍳 Waiter
```

It receives the request and sends the response back.

# 3. How do we create a Controller?

First create a package:

```text
com.example.crud
│
├── CrudApplication.java
│
└── 📁 controller
```

Inside `controller`, create:

```text
StudentController.java
```

Example:

```java
package com.example.crud.controller;

import org.springframework.web.bind.annotation.RestController;

@RestController
public class StudentController {

}
```

The important annotation is:

```java
@RestController
```

---

# 4. What is `@RestController`?

`@RestController` tells Spring:

> **This class will handle REST API requests.**

Example:

```java
@RestController
public class StudentController {

}
```

Spring sees this class and registers it as a Controller.

Conceptually:

```text
@RestController
       ↓
🔍 Spring finds the class
       ↓
🫘 Creates a Spring Bean
       ↓
🎮 Controller can handle HTTP requests
```

---

# 5. Your first Controller 🚀

Let's create a very simple Controller.

```java
package com.example.crud.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class StudentController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello Spring Boot";
    }
}
```

Now start your Spring Boot application.

Open:

```text
http://localhost:8080/hello
```

You should get:

```text
Hello Spring Boot
```

# 6. What happened here?

### `@RestController`

> This class handles REST requests.

---

### `@GetMapping`

```java
@GetMapping("/hello")
```

Means:

> When a client sends a GET request to `/hello`, execute this method.

### Method

```java
public String hello() {
```

The method returns:


```text

       ↓

       ↓
```

# 7. What is HTTP? 🌐

Before going further, understand this word:

### HTTP

**HTTP = HyperText Transfer Protocol**

HTTP is the protocol used for communication between clients and servers.

For example:

```text
🌐 Browser
   ↓ HTTP request
🚀 Spring Boot
   ↓ HTTP response
🌐 Browser
```

Common HTTP methods are:

```text
GET
POST
PUT
DELETE
```

These are very important for CRUD.

---

# 8. GET 📥

`GET` is normally used to **retrieve/read data**.

Example:

```text
GET /students
```

Meaning:

> Give me the students.

Controller:

```java
@GetMapping("/students")
public String getStudents() {
    return "List of students";
}
```

Request:

```text
GET http://localhost:8080/students
```

Response:

```text
List of students
```

---

# 9. POST 📤

`POST` is normally used to **create new data**.

Example:

```text
POST /students
```

Meaning:

> Create a new student.

Controller:

```java
@PostMapping("/students")
public String addStudent() {
    return "Student added";
}
```

---

# 10. PUT ✏️

`PUT` is normally used to **update existing data**.

Example:

```text
PUT /students/1
```

Meaning:

> Update student whose ID is 1.

Controller:

```java
@PutMapping("/students/{id}")
public String updateStudent(@PathVariable int id) {
    return "Student updated: " + id;
}
```

---

# 11. DELETE 🗑️

`DELETE` is normally used to **delete data**.

Example:

```text
DELETE /students/1
```

Meaning:

> Delete student whose ID is 1.

Controller:

```java
@DeleteMapping("/students/{id}")
public String deleteStudent(@PathVariable int id) {
    return "Student deleted: " + id;
}
```


# 15. What is `@PathVariable`?

Suppose you have:

```text
GET /students/10
```

Here:

```text
10
```

is part of the URL.

You can capture it using:

```java
@GetMapping("/students/{id}")
public String getStudent(@PathVariable int id) {
    return "Student ID: " + id;
}
```

If you request:

```text
GET /students/10
```

Response:

```text
Student ID: 10
```

Another request:

```text
GET /students/25
```

Response:

```text
Student ID: 25
```

So:

```text
/students/{id}
          ↑
       variable
```

# 16. What is `@RequestBody`?

When creating a student, the client might send JSON:

```json
{
    "name": "Ashika",
    "age": 22
}
```

The Controller can receive this JSON using:

```java
@PostMapping("/students")
public String addStudent(@RequestBody Student student) {
    return student.getName();
}
```

Here:

```text
📄 JSON
 ↓
@RequestBody
 ↓
👨‍🎓 Student object
```

Spring converts the JSON into a Java object for you.

# 17. A simple Controller example

Let's combine what we learned.

```java
package com.example.crud.controller;

import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/students")
public class StudentController {

    @GetMapping
    public String getStudents() {
        return "All students";
    }

    @GetMapping("/{id}")
    public String getStudent(@PathVariable int id) {
        return "Student ID: " + id;
    }

    @PostMapping
    public String addStudent() {
        return "Student added";
    }

    @PutMapping("/{id}")
    public String updateStudent(@PathVariable int id) {
        return "Student updated: " + id;
    }

    @DeleteMapping("/{id}")
    public String deleteStudent(@PathVariable int id) {
        return "Student deleted: " + id;
    }
}
```

# 18. What is `@RequestMapping("/students")`?

We have:

```java
@RequestMapping("/students")
```

at the class level.

So instead of writing:

```java
@GetMapping("/students")
@PostMapping("/students")
```

we can write:

```java
@GetMapping
@PostMapping
```

because `/students` is already defined.

So:

```text
@RequestMapping("/students")
        ↓
     🎮 Controller
        ↓
 ┌──────┼─────────┐
 ↓      ↓         ↓
GET    POST      PUT
```

For example:

```text
GET    /students
GET    /students/1
POST   /students
PUT    /students/1
DELETE /students/1
```

# 19. Controller does NOT usually contain business logic ⚠️

This is very important.

A beginner might write:

```java
@RestController
public class StudentController {

    @GetMapping("/students")
    public String getStudents() {

        // 100 lines of business logic
        // database code
        // calculations
        // validations

        return "...";
    }
}
```

This is **not a good architecture**.

Instead:

```text
🎮 Controller
      ↓
⚙️ Service
      ↓
🗄️ Repository
      ↓
🐬 Database
```

Controller's main responsibility is handling the request/response.

# ⭐ Interview answer

If the interviewer asks:

### "What is a Controller in Spring Boot?"

You can say:

> **A Controller is a Spring component responsible for handling HTTP requests and returning responses to the client. In REST APIs, we commonly use `@RestController` along with annotations such as `@GetMapping`, `@PostMapping`, `@PutMapping`, and `@DeleteMapping` to handle different HTTP operations.**

### Remember the flow:

```text
👤 Client
  ↓
🎮 Controller     ← HTTP request/response
  ↓
⚙️ Service        ← Business logic
  ↓
🗄️ Repository     ← Database operations
  ↓
🐬 MySQL
```

The **next layer after Controller is Service**, which is where we put the **business logic**.
